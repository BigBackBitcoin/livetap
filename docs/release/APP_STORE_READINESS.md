Audited 2026-09-11 against the checklist in
[`docs/research/DESKTOP_MOBILE_STORE_RESEARCH.md`](../research/DESKTOP_MOBILE_STORE_RESEARCH.md) §3.3.
Host: Windows Server 2022, Node 20.11, **no Xcode, no macOS, no Apple Developer account, no device**.

This is an audit of **files that exist in this repository**, not an aspiration. Where the research
document says "PASS (implementable)", this audit asks the harder question — *is it implemented
here?* — and answers **FAIL** when it is not. That is why several rows are worse than the research
suggested.

## Appendix B — App Review notes, draft

Points worth stating up front, because a reviewer cannot discover them by tapping:

1. **LIVETAP has no account.** There is nothing to sign in to, so there are no test credentials. To
   review the full flow, connect any YouTube or Twitch account, or use a Custom RTMP destination.
2. **`UIBackgroundModes: audio` is used for a real audio feature.** A live broadcast must survive
   the user glancing at a notification; iOS stops the camera in the background (by design), and the
   app continues audio-only and tells the user their camera is paused. It is not used to keep the
   app alive.
3. **Destination OAuth is not a login (4.8).** Connecting YouTube/Twitch authorises publishing to
   the user's own channel. It does not create or authenticate a LIVETAP account, and there is no
   LIVETAP account to create.
4. **LIVETAP never receives the broadcast.** Media goes device → platform. There is no LIVETAP
   server in the path, which is why the app has no server-side content kill switch: the platform
   the user is broadcasting to owns that.
5. **Third-party ingest is required for a meaningful demo.** A reviewer without a connected channel
   can still exercise preview, camera switch, mute and recording.
